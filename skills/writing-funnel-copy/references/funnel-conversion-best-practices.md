# Web Funnel Conversion Best Practices

Use this as an experiment menu, not a mandatory screen inventory. The historical teardowns show execution patterns; they do not establish causal uplifts for your product.

| Opportunity | Test | Check beyond the immediate click |
| --- | --- | --- |
| Entry mismatch | Align the first action and headline with one creative promise. | Purchase, net revenue per landing, CAC by creative. |
| Unrewarded questions | Return a useful insight or product-specific feedback. | Completion, purchase, result accuracy. |
| Generic result | Reflect meaningful prior answers and explain the mechanism. | Purchase, activation, support complaints. |
| Low confidence | Add relevant, sourced proof at the decision point. | Purchase and refunds; never invent authority. |
| Confusing offer | Simplify plan comparison and clarify initial/renewal charges. | Net revenue, plan mix, renewal retention. |
| Checkout friction | Improve supported express methods and recoverable errors. | Successful payments, duplicate-charge risk, abandonment. |
| Checkout abandonment | Test an optional close offer or consented reminder. | Incremental revenue after discounts, refunds, opt-outs. |
| Weak handoff | Clarify next steps and make account/access recovery reliable. | Activation, entitlement failures, renewal retention. |

Question count, cadence, visual style, and loader duration follow the useful content and actual work. A 30-second story sequence and a short processing indicator serve different purposes; neither should pretend a computation that did not occur.

For recovery messages, distinguish unpaid checkout abandonment from paid-but-unactivated users. Confirm contact permission, suppress reminders after purchase, preserve unsubscribe, and compare against a holdout. Attributed recovery revenue is not automatically incremental or attributable to email alone.

Before running a test, define audience, assignment/exposure event, one primary metric, guardrails, minimum detectable effect, analysis method, decision rule, and sample/runtime requirements. Check allocation and tracking integrity first. Avoid stopping a fixed-horizon test on the first favorable result; use a valid sequential method when continuous monitoring is intended.

Use the course's [experimentation lesson](../../web2app-essentials/references/11-experimentation.md) for the analysis workflow. Keep full case studies in source history rather than appending them to this checklist.
