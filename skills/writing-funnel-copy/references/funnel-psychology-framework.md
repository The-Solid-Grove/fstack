# Funnel Psychology Engine

Use mental fuel as a design metaphor: questions and confusing interfaces cost attention; relevant feedback and credible value help the user decide whether to continue. It is not a measured psychological quantity or a formula for predicting conversion.

## Pre-work for a new funnel

Create a five-column table: **problems · why current solutions fail · purchase barriers · concrete benefits · desired emotional outcome**. Use real product and audience evidence, then write the transformation and entry promise in one sentence each.

## Build the narrative

| Part | Screen job |
| --- | --- |
| Hook | Continue the ad promise and invite an easy, relevant first action. |
| Discovery | Ask questions whose answers affect the experience or explain fit. |
| Value | Return useful feedback, show the mechanism, and address the main objection. |
| Result | Reflect actual answers, explain uncertainty, and connect the result to the offer. |
| Identity | Explain why the identifier is needed and how it will be used. |
| Offer | Recap relevant value, disclose billing terms, and make the purchase choice clear. |

These are narrative jobs, not fixed step counts. Combine or repeat where the product warrants it. After a cluster of questions, check whether the user has received useful feedback; avoid filler interstitials added only to satisfy a cadence.

## Screen rules

- One clear idea and primary action. A quick glance should reveal the screen's purpose.
- Concise headline and body. Six-word headlines and one or two short sentences are editing defaults, not limits on necessary explanations or disclosures.
- Let evidence support the conclusion: an actual product preview, a defensible comparison, or a result derived from the user's inputs. State limitations alongside claims.
- Use visuals to explain value. Choose faces, charts, or animation only when they serve the screen; fixed attention-percentage claims are not evidence.
- Start with low-effort, low-sensitivity questions. Explain why personal information is needed and provide supported skip paths.
- Acknowledge difficulty without shaming users or exaggerating fear. Present alternatives fairly; declining is a valid choice.
- Match the next screen to what the previous CTA promised. Honest progress and real processing messages preserve trust.
- Ranges, testimonials, authority logos, guarantees, and comparisons require evidence. A range does not make an unsupported outcome safe to claim.

For an existing screen edit, use the relevant rules directly; full pre-work and a whole-funnel deliverable are unnecessary.

## Deliverable for a new or redesigned funnel

1. Five-column pre-work table, transformation, and entry promise.
2. Screen map showing the narrative job and effort/value balance, without invented fuel scores.
3. Screen-by-screen spec: headline, body, choices, CTA, visual direction, actual personalization, and intended transition. Map implementation through the project's managed docs separately.
4. Paywall architecture with first charge, renewal terms, evidence, objections, and access expectations.
5. A short prioritized experiment list: hypothesis, primary outcome, and guardrails.
