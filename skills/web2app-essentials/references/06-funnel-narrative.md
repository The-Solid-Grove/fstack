# 6. Funnel architecture: mental energy and storytelling

Turn the brief into a sequence where each request has a purpose and each useful answer receives a meaningful response.

## Balance effort and value

**Mental energy** is a design metaphor for attention and willingness to continue, not a scientific quantity or an analytics score. Measure completion, time, exits, errors, and downstream purchase quality.

An **ask** requires effort: choosing, reading, entering data, waiting, or deciding. A **give** returns value: a relevant explanation, demonstration, result, feedback, or resolved uncertainty. A screen can do both.

Review clusters of questions for fatigue. Return useful value before another substantial request; use the cost of the input and the value of the response to judge timing. Generic praise does not explain how an answer matters.

## Give each part a job

These are narrative roles, not a mandatory inventory of screens. Combine them when one screen can do the work clearly.

| Role | What it must accomplish |
| --- | --- |
| Expectation match | Continue the creative's specific promise with one clear next action. |
| Self-recognition | Ask about goals and observable context. Use each answer in the flow or label it honestly as research. |
| Mechanism | Explain the difficulty and the product's approach without blaming the person. Demonstrate with a relevant example, comparison, or real product behavior. |
| Feedback | Show how a meaningful answer changes the explanation or recommendation. Branch only where the content differs. |
| Future state | Make the potential result concrete through a supported plan, preview, or trajectory. Back scores, dates, ranges, and predictions with evidence or a real model, and state assumptions. |
| Preparation | Ask for a commitment or preference only if it affects the plan. Describe real processing; use an ordinary transition when no analysis is happening. |
| Identity and offer | Collect email for an actual function, such as saving, delivery, or access. Place it where that function requires it. Connect the offer to the value already demonstrated. |

Verify scientific, medical, financial, and legal claims before using them. Keep results proportionate to the information collected; completing a quiz does not establish an outcome.

## Map every screen

| Field | Record |
| --- | --- |
| Job | Why the screen exists |
| Message | The single idea to remember |
| Energy | Effort asked and value returned |
| Input | The required action |
| Payoff | What the person receives |
| Data | Where the answer is stored and used |
| Next | Normal and branching transitions |
| Proof | Evidence needed for the claim |

Use the shortest sequence that fulfills the entry promise, gathers useful context, demonstrates the mechanism, returns a relevant result, resolves key barriers, and explains the offer. Screen count alone says little about quality.

Check the opening's loading speed, mobile layout, creative match, first action, and behavior in in-app browsers. Later improvements cannot recover visitors who never pass the opening.

## Exercise

Audit the screen map: remove unused questions and screens without a job, add useful feedback where effort accumulates, and trace each offer claim to earlier evidence. Briefly show each screen to a reader and check the idea and next action they understood. Treat this as an editing check, not a measured psychological threshold.
