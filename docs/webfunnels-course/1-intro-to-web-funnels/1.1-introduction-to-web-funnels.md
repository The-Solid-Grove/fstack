## What web funnels are

A web funnel is a browser-based flow (landing page, quiz, article, or video page) that sits between the ad and the sale, instead of sending traffic straight to an app store. The main models:

| Model | Flow | Where the purchase happens |
|---|---|---|
| **App** (classic) | Ad → app store install → purchase | In-app (full app product) |
| **Web2App** | Ad → web landing page → app install → purchase | In-app (web is a pre-sell layer) |
| **Web2Web** | Ad → web landing page → **purchase on web** → app install | On web (web experience + paywall) |
| **Web** (full web) | Ad → web landing page → purchase | On web (full web product) |

Common funnel formats:

- Web2app redirect straight to the App Store ("fake App Store" page)
- Landing pages presenting the product
- **Quizzes / questionnaires** (the core format for quiz-to-paywall funnels)
- Advertorial / blog / forum pre-landers
- Video sales letters (VSL)

## Why do it (and why it's hard)

### Costs and downsides — go in with open eyes

1. **Extra friction**: another layer between ad and sale.
2. **Lower trust** on a third-party website than on the App Store — conversion suffers (you're not Apple).
3. **Real resource cost**: expect roughly one dedicated full-stack growth team; it dilutes focus.
4. **New processes and infrastructure**: payment providers, subscription management and analytics, support/CRM, localization and currencies, taxes, chargebacks, refunds.

### Strong advantages

1. **Transparent tracking and user-level attribution** — no SKAN/ATT limitations.
2. **New audiences and inventory**: a different ad auction (e-commerce buyers instead of app installers), new web channels (Google Search, Taboola, etc.), affiliate and partner traffic.
3. **Better storytelling and personalization**: the funnel warms the user up; you can personalize the whole flow from creative to checkout; A/B testing is technically easy (no app releases needed).
4. **Full control over payments and subscriptions**: no 30% App Store commission, no 60-day payout delay, custom payment products, extra payment methods, control over cancellation flows.

### Proof it works at scale

Top apps running web funnels (SensorTower, Oct 2023; SensorTower doesn't see web2web revenue, so real numbers are higher):

## The unit economics

Same UA formula as any acquisition channel: **CAC < LTV**, improved through a continuous test-and-learn process.

```
CAC = CPM / (CTR × CR to 2nd screen × CR to paywall × CR to checkout × CR to purchase)

LTV = f(average checkout order value, subscription retention)
```

Key mental model vs iOS funnels:

- Web is different inventory and a different audience.
- Web users have **lower intent** than users who installed an app — expect worse mid-funnel conversion.
- **Higher LTV on web** (no store commission, upsells, pricing control) is what covers the higher CAC.
- Benchmarks are generalizations and vary a lot between products — **optimize for CAC and ROAS, not proxy metrics**.

### Typical funnel drop-off benchmarks

| Step | Share of funnel entrants |
|---|---|
| Land on first screen | 100% |
| Reach mid-onboarding | 35–60% |
| Reach paywall | 10–20% |
| Reach checkout | 8–15% |
| Purchase | 0.5–5% |

Highest-leverage elements to test: main storytelling, first-screen message and design, pre-paywall, paywall, checkout form.

## How to build a web funnel: the optimization order

Work in this order — each stage gates the next:

### 1. Start with ad creatives and UA setup

- Creatives are the single biggest lever: one team saw funnel CVR move **from 0.3% to 1.5% on creative changes alone**.
- Running web-funnel experiments is useless if creatives are poor or you're acquiring the wrong audience.
- It's fine to launch with a mediocre funnel and strong creatives — not the reverse.
- What works in iOS/Android creatives usually works for web funnels too.

### 2. Optimize onboarding

- **Know the user's "job" and sell the solution**: show topic expertise and understanding of the user's needs and pains.
- **Feedback loops**: react to the user's quiz answers with tailored responses.
- **Build trust and FOMO**: user reviews, before/after visuals, urgency.
- **Deliver value before payment**: show the product or let the user try it; give personalized feedback and educate.
- Proven onboarding elements: trust-building screens, value/education screens, answer-driven feedback loops, "analyzing your answers" loaders.
- **Optimize for mobile webviews** (Instagram, Facebook, TikTok in-app browsers) and remove every bit of friction.

### 3. Improve the payment process

- Test paywall variations:
  - Price configurations: week, month, 3-month, 6-month, year, lifetime
  - Trials vs straight subscription
  - Intro offers (e.g. **$4.99 for the first week converting to $28.49/month**)
  - Discounts
- Proven paywall experiments: countdown timers, prices shown per day/week/month, before/after imagery, "choose your trial price", upgrade-to-longer-plan offers, after-purchase upsells (e.g. a PDF workbook).
- Add upsells and one-time purchases on top of the subscription.

### 4. Build infrastructure

- **Payments**: PSPs (Stripe, Braintree, Adyen, etc.), payment methods (PayPal, Apple Pay, Google Pay), fraud monitoring and chargeback prevention, chargeback management, currencies and local payment methods.
- **Subscription management**: subscriptions, one-time offers, pay-as-you-go, trials, intro offers, promo codes, discounts, grace periods and retry (dunning) logic.
- **Support**: ticket system, refund and chargeback resolution.
- **Analytics**: subscription analytics.
- **Experimentation**: onboarding constructor and A/B-testing tools.
